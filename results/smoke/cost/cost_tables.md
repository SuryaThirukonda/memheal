# MemHeal cost (proposal Section 8.10)

Generated by `cost.py` from 480 runs (*_dense_direct_evolving, *_dense_composed_evolving, *_dense_procedural_evolving, *_dense_direct, *_dense_composed, *_dense_procedural), by memory mode: evolving, flat. Offline: no model call, no network.

## Key numbers

- Storage (evolving, 240 runs): a run.db is 233,472 [224,256, 241,664] bytes over 51 [46, 55] memories (4,588 [4,455, 4,808] bytes per memory). Provenance tables take 44.4% [43.3%, 46.0%] of the file's pages (49.4% [48.2%, 50.9%] counting memory-row metadata), mostly fixed one-page-per-table overhead; of the stored payload they are 35.6% [34.2%, 37.0%]. Lineage is 0.60 [0.54, 0.87] edges and 37 [33, 54] payload bytes per memory (241 [223, 267] allocated). Per-session snapshot copies add 13.6 [13.2, 14.1] times the run.db.
- Storage (flat, 240 runs): a run.db is 229,376 [217,088, 237,568] bytes over 42 [38, 46] memories (5,461 [5,165, 5,713] bytes per memory). Provenance tables take 51.0% [49.2%, 52.0%] of the file's pages (55.6% [53.9%, 56.5%] counting memory-row metadata), mostly fixed one-page-per-table overhead; of the stored payload they are 38.3% [36.8%, 40.3%]. Lineage is 0.00 [0.00, 0.00] edges and 0 [0, 0] payload bytes per memory (293 [267, 323] allocated). Per-session snapshot copies add 13.4 [13.0, 14.0] times the run.db.
- Retrieval (store side, median): 9.56 ms at 30, 27.24 ms at 1,000, 198 ms at 10,000 memories; the retrieval_events write is part of that. Measured on a busy machine (see Section 2): re-measure before quoting.
- One MiniLM query encode: median 8.66 ms.
- Normal operation (evolving, 240 runs): 60 [57, 64] model calls per run over 20 [20, 21] sessions, 1,843 [1,678, 2,182] tokens per session; provenance adds no model call.
- Normal operation (flat, 240 runs): 60 [57, 62] model calls per run over 19 [19, 20] sessions, 1,820 [1,700, 2,205] tokens per session; provenance adds no model call.
- Counterfactual diagnosis (evolving; selective[cf] (patched) minus selective[oracle] (patched), per incident): +7 [5, 14] calls, +7,388 [5,126, 15,210] input tokens, +6.9 [4.4, 13.7] s.
- No-oracle recovery (evolving; incident[cf]+verify (patched), per incident, 67 incidents): 27 [22, 33] calls, 25.4 [20.9, 31.9] s, 8 [6, 8] counterfactual replays.

## 2. Latency (offline, synthetic stores)

Machine: AMD Ryzen AI 7 PRO 350 w/ Radeon 860M, 16 cores, Python 3.11.16, SQLite 3.53.1, NumPy 2.4.6. Load average (1 / 5 / 15 min) 4.17 / 1.89 / 1.68 before the benchmark and 17.92 / 5.90 / 3.04 after it. Each cell: median / p95 over 30 timed calls after 3 warm-up calls, in milliseconds. Stores are sqlite files with the real schema, 384-d random unit float32 embeddings and 90-byte texts, written to a temp folder under results/smoke/cost and deleted afterwards; k = 5; the query embedder returns a constant vector, so the encoder is not in these numbers. Calls are interleaved: each round times every store size and part once, in a shuffled order, so load from elsewhere on the machine falls on every size alike rather than on one.

**Warning: the machine was busy** (a 1-minute load average above 4.0, a quarter of the cores). Other work competed with these timings, so they overstate the store's own cost and should be re-measured on an idle machine.
